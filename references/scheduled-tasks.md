# 定时任务配置详细说明

> 本文档是 SKILL.md 定时点餐章节的详细补充，包含完整的配置步骤、参数说明和示例。

## 定时任务方案对比

| 方案 | 执行频率 | 任务数量 | 单次点餐量 | 配置复杂度 | 适用场景 |
|------|---------|---------|-----------|-----------|---------|
| **方案一：周日点整周**（推荐） | 1次/周（周日） | 1个 | 下周5天×3餐=15餐 | **最低** | 提前规划整周餐食 |
| **方案二：每日点次日** | 5次/周（周一到周四+周日） | 1个（多触发器） | 1天×3餐=3餐 | 中等 | 每日动态调整偏好 |
| **方案三：抢餐任务** | 按需配置 | 1个 | 按需 | 中等 | 等待特定餐厅开放 |

## 方案一：周日点整周（推荐）

### 执行时间表

- 执行日：周日
- 执行时间：19:00-21:00 随机（建议分散峰值）
- 点餐目标：下周周一到周五（5天）
- 参数：`--week`

### Windows 任务计划程序配置

> **⚠️ 强制约束**：**严禁直接使用示例时间（如 19:47、19:35）**。
> 必须由 Agent 动态生成 0-120 的随机整数，加到 19:00 计算出实际执行时间。

**配置步骤**：
1. 打开"任务计划程序"（搜索 `taskschd.msc`）
2. 点击"创建基本任务"
3. 名称："美餐-周日点整周"
4. 触发器：每周，周日，时间（由 Agent 随机生成）
5. 操作：启动程序
   - 程序：`python`
   - 参数：`<SKILL_DIR>\scripts\order_meal.py --week`
6. 完成

**配置模板**：
```
程序：python
参数：<SKILL_DIR>\scripts\order_meal.py --week
触发器：每周日 {随机HH:MM}（时间由 Agent 配置时随机生成）
```

### Linux/Mac crontab 配置

> **⚠️ 强制约束**：**严禁直接使用示例时间（如 19:47、19:35）**。
> 必须由 Agent 动态生成 0-120 的随机整数，加到 19:00 计算出实际执行时间。

**配置步骤**：
1. 执行：`crontab -e`
2. 添加以下行（时间由 Agent 随机生成）：
```cron
# 周日 {随机HH:MM} 点下周整周（周一到周五，时间由 Agent 配置时随机生成）
MM HH * * 0 python <SKILL_DIR>/scripts/order_meal.py --week
```
3. 保存退出

**时间说明**：
- `MM HH`：由 Agent 随机生成的时分（19:00 + 0~120 分钟）
- `* * 0`：每周日
- 随机生成避免扎堆被风控

## 方案二：每日点次日

### 执行时间表

| 执行日 | 执行时间 | 点餐目标 | 参数 |
|--------|----------|----------|------|
| 周一 | 19:00-21:00 随机 | 周二 | `--date "+1"` |
| 周二 | 19:00-21:00 随机 | 周三 | `--date "+1"` |
| 周三 | 19:00-21:00 随机 | 周四 | `--date "+1"` |
| 周四 | 19:00-21:00 随机 | 周五 | `--date "+1"` |
| 周日 | 19:00-21:00 随机 | 周一 | `--date "+1"` |

> **周五、周六不执行**：周六、周日通常无点餐时段。

### Windows 任务计划程序配置

> **⚠️ 强制约束**：**严禁直接使用示例时间（如 19:47、19:35）**。
> 必须由 Agent 动态生成 0-120 的随机整数，加到 19:00 计算出实际执行时间。

**配置模板**：
```
程序：python
参数：<SKILL_DIR>\scripts\order_meal.py --date "+1"
触发器：每周一、二、三、四、日 {随机HH:MM}（时间由 Agent 配置时随机生成）
```

**注意**：使用同一个随机时间，避免多次生成。

### Linux/Mac crontab 配置

> **⚠️ 强制约束**：**严禁直接使用示例时间（如 19:47、19:35）**。
> 必须由 Agent 动态生成 0-120 的随机整数，加到 19:00 计算出实际执行时间。

**配置模板**：
```cron
# 周一、二、三、四、日 {随机HH:MM} 点次日三餐（时间由 Agent 配置时随机生成）
MM HH * * 1-4,0 python <SKILL_DIR>/scripts/order_meal.py --date "+1"
```

**注意**：
- `1-4`：周一到周四
- `0`：周日（cron 中周日=0）
- `1-4,0`：周一到周四 + 周日
- `MM HH`：由 Agent 随机生成的时分（19:00 + 0~120 分钟）
- 随机生成时间避免扎堆被风控

## 方案三：抢餐任务

> 抢餐任务用于等待特定餐厅开放后自动下单，适用于餐厅开放时间不确定的场景。

### 用户表述关键词

当用户提到以下关键词时，Agent 理解为抢餐场景：
- `抢餐`
- `抢订`
- `抢XX餐厅`
- `等待餐厅`
- `等到开放`
- `开放时间不确定`

### 参数映射表

| 用户表述 | 参数 | 示例 |
|---------|------|------|
| "抢麦当劳" | `--wait-restaurant` | `--wait-restaurant "麦当劳"` |
| "最多等10次" | `--wait-retry` | `--wait-retry 10`（默认） |
| "每次等5分钟" | `--wait-interval` | `--wait-interval 300`（默认） |
| "点周四" | `--date` | `--date "+3"`（周六+3=周四） |
| "午餐" | `--tab` | `--tab "午餐"` |

### 配置示例

#### 示例1：周六抢周四午餐（麦当劳）

**用户表述**：
```
"帮我配置周六中午抢周四午餐的麦当劳"
```

**Agent 生成配置**：
```cron
# 周六 12:00 抢周四午餐（麦当劳）
0 12 * * 6 python <SKILL_DIR>/scripts/order_meal.py --date "+5" --tab "午餐" \
  --wait-restaurant "麦当劳" --wait-retry 10 --wait-interval 300
```

**配置说明**：
- 执行时间：周六 12:00（麦当劳可能在中午开放）
- 目标日期：周四（周六 + 5 天）
- 时间段：午餐
- 等待餐厅：麦当劳
- 重试次数：最多 10 次
- 等待间隔：每次随机 300-600 秒
- 预估最长等待：10 × 600 = 6000 秒（约 1.7 小时）

#### 示例2：周日抢下周一午餐（特定餐厅）

```cron
# 周日 12:00 抢下周一午餐（湘菜馆）
0 12 * * 0 python <SKILL_DIR>/scripts/order_meal.py --date "+1" --tab "午餐" \
  --wait-restaurant "湘菜馆"
```

#### 示例3：自定义等待参数

```cron
# 周二 18:00 抢周三晚餐，最多等15次
0 18 * * 2 python <SKILL_DIR>/scripts/order_meal.py --date "+1" --tab "晚餐" \
  --wait-restaurant "肯德基" --wait-retry 15 --wait-interval 300
```

## Agent 配置引导流程

> **⚠️ 强制约束**：**严禁直接使用示例时间（如 19:47、19:35）**。
> 必须由 Agent 动态生成 0-120 的随机整数，加到 19:00 计算出实际执行时间。

> **⚡ Agent 执行规范**：配置定时任务时，生成 0-120 的随机分钟数，换算为 HH:MM 格式。

### 随机时间生成规则

**Windows 任务计划程序**：
- 生成 0-120 的随机分钟数
- 加到 19:00 得到执行时间
- 示例：随机 47 → 执行时间 19:47

**Linux/Mac crontab**：
- 生成 0-120 的随机分钟数
- 换算为小时和分钟
- 示例：
  - 随机 47 分钟 → `47 19`（19:47）
  - 随机 95 分钟 → `0 20`（20:00）
  - 随机 120 分钟 → `0 21`（21:00）

## 与每日点餐的配合

### 避免重复下单

- 方案一和方案二可以同时配置
- 已下单检查机制确保不重复下单
- 如果用户在周日同时执行了两种方案：
  - 方案一：点下周周一到周五
  - 方案二：点下周一
  - 结果：方案二检测到周一已下单，跳过

### 推荐配置策略

**策略一：只用方案一**
- 周日一次性点整周，简单高效
- 适合提前规划的用户

**策略二：只用方案二**
- 每日点次日，灵活调整
- 适合每日动态调整偏好的用户

**策略三：方案一 + 方案二补充**
- 周日点整周（主方案）
- 每日点次日（补充，已下单自动跳过）
- 适合需要灵活调整的用户

## 已下单检查机制

脚本执行时通过美餐 API 查询线上订单状态，确保不重复下单。

### 执行模式区分

**定时任务模式（无 --tab 参数）**：
- 查询目标日期所有可用时段的订单状态
- 仅对未下单时段执行补单
- 若三餐均已下单 → 打印摘要并退出

**手动指定模式（有 --tab 参数）**：
- 仅查询指定时段的订单状态
- 不检查其他时段

### 特殊日期处理

某些日期可能只有部分时段可用：
- 如周五无早餐时段
- 自动跳过不可用时段，不报错
