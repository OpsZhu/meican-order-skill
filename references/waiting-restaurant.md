# 等待餐厅开放详细说明

> 本文档是 SKILL.md --wait-restaurant 参数的详细补充，包含完整的工作流程、参数说明、场景示例和 Agent 配置指引。

## 功能概述

`--wait-restaurant` 参数用于等待指定餐厅开放后自动下单，适用于餐厅开放时间不确定的场景（如"麦当劳"可能在特定时间才开放）。

**主要用途**：
- 抢订特定餐厅的菜品
- 等待餐厅开放时间不确定的场景
- 提前配置定时任务，自动等待餐厅开放

---

## 参数说明

### 参数列表

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `--wait-restaurant` | 字符串 | 无 | 等待餐厅名称（模糊匹配） |
| `--wait-retry` | 整数 | 10 | 最大重试次数 |
| `--wait-interval` | 整数 | 300 | 基准等待秒数（实际随机 300-600） |

### 参数详解

#### --wait-restaurant（餐厅名称）

**匹配方式**：模糊匹配餐厅名称

**示例**：
- `--wait-restaurant "麦当劳"` → 匹配包含"麦当劳"的餐厅
- `--wait-restaurant "湘菜"` → 匹配包含"湘菜"的餐厅（如"湘菜馆"、"湘菜小炒"）

#### --wait-retry（重试次数）

**用途**：控制最大等待时长

**示例**：
- `--wait-retry 10`：最多重试 10 次
- `--wait-retry 15`：最多重试 15 次

**最长等待计算**：`--wait-retry × 600` 秒

#### --wait-interval（等待间隔）

**用途**：控制每次等待时长

**默认行为**：实际等待为随机值（interval 到 interval×2 之间）

**示例**：
- `--wait-interval 300`：每次等待随机 300-600 秒
- `--wait-interval 600`：每次等待随机 600-1200 秒

**随机等待的原因**：
- 避免多人设置相同间隔导致同时重试
- 分散美餐服务端请求峰值
- 每次等待时间随机，但保持在合理范围

## 工作流程

### 流程图

```
脚本启动 → 查询目标时段餐厅列表
    ↓
检查指定餐厅是否出现
    ├─ 出现 → 立即下单 ✓
    └─ 未出现 → 等待随机时间（300-600秒）
        ↓
    重试查询餐厅列表
        ├─ 出现 → 下单 ✓
        └─ 未出现 → 继续等待重试
            ↓
        达到最大重试次数
            ├─ 餐厅出现 → 下单 ✓
            └─ 超时 → 输出失败信息，exit 1 ✗
```

```

[等待] 已等待约 456 秒，剩余最多约 2700 秒

[等待] 第 2 次检查：餐厅未出现
[等待] 本次等待 512 秒（随机范围 300-600）后重试...

## 使用场景

### 场景一：等待餐厅开放后点餐

**用户需求**："麦当劳"只在中午12点开放，要等它开放后点餐

**执行命令**：
```bash
python <SKILL_DIR>/scripts/order_meal.py --date "+3" --tab "午餐" \
  --wait-restaurant "麦当劳"
```

**默认参数**：
- 重试次数：10 次
- 等待间隔：每次随机 300-600 秒
- 预估最长等待：6000 秒（约 1.7 小时）

---

### 场景二：等待餐厅 + 关键字筛选

**用户需求**：等待"麦当劳"开放后，优先选牛腩、鸡、排骨类菜品

**执行命令**：
```bash
python <SKILL_DIR>/scripts/order_meal.py --date "+3" --tab "午餐" \
  --wait-restaurant "麦当劳" --expect "牛腩|鸡|排骨"
```

**筛选逻辑**：
1. 等待"麦当劳"出现
2. 从该餐厅菜品中筛选含"牛腩"、"鸡"、"排骨"的菜品
3. 若匹配不到，从该餐厅其他菜品中随机选择

---

### 场景三：自定义等待参数

**用户需求**：最多等15次，每次等待5-10分钟

**执行命令**：
```bash
python <SKILL_DIR>/scripts/order_meal.py --date "+3" --tab "午餐" \
  --wait-restaurant "麦当劳" --wait-retry 15 --wait-interval 300
```

**最长等待计算**：15 × 600 = 9000 秒（约 2.5 小时）

## 定时任务配置

### 配置要点

**关键参数映射**：

| 用户表述 | 参数 | 示例 |
|---------|------|------|
| "抢麦当劳" | `--wait-restaurant` | `--wait-restaurant "麦当劳"` |
| "周六中午执行" | cron 时间 | `0 12 * * 6` |
| "点周四" | `--date` | `--date "+3"`（周六+3=周四） |
| "午餐" | `--tab` | `--tab "午餐"` |

### 完整配置示例

#### 示例1：周六抢周四午餐

**用户表述**：
```
"配置周六中午抢周四午餐的麦当劳"
```

**配置结果**：
```cron
# 周六 12:00 抢周四午餐（麦当劳）
0 12 * * 6 python <SKILL_DIR>/scripts/order_meal.py --date "+3" --tab "午餐" \
  --wait-restaurant "麦当劳" --wait-retry 10 --wait-interval 300
```

**配置说明**：
- 执行时间：周六 12:00
- 目标日期：周四（周六 + 3 天）
- 时间段：午餐
- 等待餐厅：麦当劳
- 重试次数：最多 10 次
- 等待间隔：随机 300-600 秒

---

#### 示例2：周日抢下周一午餐

**用户表述**：
```
"配置周日抢下周一午餐的湘菜馆"
```

**配置结果**：
```cron
# 周日 12:00 抢下周一午餐（湘菜馆）
0 12 * * 0 python <SKILL_DIR>/scripts/order_meal.py --date "+1" --tab "午餐" \

```

#### 示例3：周二抢周三晚餐

## Timeout 建议

**建议 timeout**：7200 秒（约 2 小时）

**计算依据**：
- 最长等待：10 × 600 = 6000 秒（约 1.7 小时）
- 下单耗时：约 30-60 秒
- 留有余量：7200 秒

**自定义 timeout 计算**：
```
timeout = --wait-retry × 600 + 1200（下单时间余量）
```

## 常见问题

### Q1：如果餐厅一直没有出现？

**回答**：脚本达到最大重试次数后，输出失败信息并 exit 1。失败信息包含预估等待时长和重试次数。

### Q2：等待期间可以手动下单吗？

**回答**：不建议。如果等待期间手动下单，脚本继续等待餐厅出现后可能会重复下单。建议等待脚本完成后再决定。

### Q3：随机等待时间如何生成？

**回答**：脚本每次等待时，生成随机值（interval 到 interval×2 之间）。例如 interval=300 → 等待 300-600 秒之间。

### Q4：可以多个定时任务同时等待同一餐厅吗？

**回答**：可以，但建议使用不同的随机时间（不同的 --wait-interval），避免同时重试导致服务端压力过大。

## 与其他参数的配合

### 与 --expect 配合

**用途**：等待餐厅出现后，按关键字筛选菜品

**示例**：
```bash
--wait-restaurant "麦当劳" --expect "牛腩|鸡|排骨"
```

**逻辑**：
1. 等待"麦当劳"出现
2. 从该餐厅菜品中筛选含关键字的菜品
3. 若匹配不到，从该餐厅其他菜品中随机选择

### 与 --exclude 配合

**用途**：等待餐厅出现后，排除特定菜品

**示例**：
```bash
--wait-restaurant "麦当劳" --exclude "辣|炸"
```

### 与 --no-prefs 配合

**用途**：等待餐厅出现后，不使用偏好筛选

**示例**：
```bash
--wait-restaurant "麦当劳" --no-prefs
```

## 向后兼容

**不传 --wait-restaurant 时**：
- 脚本立即查询餐厅列表
- 不等待、不重试
- 行为与之前版本一致

**新参数不影响现有功能**：
- `--list`：仅列出菜品
- `--cancel`：取消订单
- `--reorder`：重新点餐
- 这些功能不受 --wait-restaurant 影响
